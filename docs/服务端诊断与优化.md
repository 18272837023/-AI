# 服务端诊断（2026-10-31）

结论：P0 单机服务端骨架已实现，规则模拟链路可运行；尚未达到可上线产品的完成度。接口跑通不代表真实模型质量、前端接入或部署验收完成。

## 已实现

12 个 HTTP 路由；异步任务与轮询；文本 PDF、DOCX、TXT 解析；四阶段生成；结构化模型输出校验；规则自检；本地 JSON 持久化。默认 mock 不调用模型。

## 本次优化

- 修复重新上传后仍解析第一份文件：现在使用最新文件，摘要也显示最新文件。
- 上传或重跑上游时清除旧产物及元信息，避免新解析与旧正文混用。
- 同项目阶段互斥，上传也受保护；同阶段重复提交继续复用任务。
- 将 URL 解码错误纳入异常处理；拒绝 null、数组等 JSON 请求以及非法项目名。
- 超大请求返回 413，不再主动断开连接导致客户端只收到网络错误；停止缓存超限数据。
- 规则模拟及模型失败后的兜底同样经过 Schema 校验。
- 修复任务完成进度被覆盖为 99% 的问题。
- 拒绝把旧版 DOC 错认成 DOCX。
- 新增隔离临时数据的自动化接口回归测试，修复 npm test 入口。

## 后续优先级

| 优先级 | 缺口 | 建议 |
|---|---|---|
| 高 | 小程序仍基于 mock 和内存状态 | 接入建项目、真实上传、任务轮询及服务端结果；保留可切换演示模式 |
| 高 | 没有登录、项目归属及接口鉴权 | 公网部署前实现微信登录和项目级权限隔离；当前只适合受控本机使用 |
| 高 | 没有服务端正文/要素编辑保存和实际导出接口 | 补充人工确认、保存及导出门禁，贯通编辑到文件交付 |
| 高 | 真实模型质量未验收 | 用脱敏真实标书验证抽取准确率、评分覆盖、证据原文和占位符，不以示例通过代替验收 |
| 高 | 长文在提示词中每节截取 2600 字，并只选择部分章节 | 增加分块抽取、合并去重及证据覆盖检查，避免遗漏后段评分条款 |
| 中 | JSON 单文件、内存队列 | 单进程试用可保留；多用户部署前改数据库和可恢复任务，增加备份、限流及队列上限 |
| 中 | 缺少 OCR | 扫描 PDF 需专门识别；当前应明确告知用户改用文字版 |
| 中 | 规则评分抽取单项上限 20 分 | 有漏掉真实高分单项的风险，后续改用标题、表格上下文判定总述行 |

## 验证范围

本次通过本机 HTTP 测试运行规则模拟全链，并验证异常输入、任务互斥、文件替换、上游重跑清理、Schema 及进度。未调用付费模型，未修改现有项目数据，未部署公网，也未对真实标书质量作保证。
