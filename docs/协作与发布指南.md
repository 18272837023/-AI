# 团队协作与发布指南

> 面向：接手本项目的同事、以及需要发版的人。

---

## 一、项目性质

这是**微信原生小程序工程**，不是 H5、不是 uni-app、不是 Taro。

- 没有 `package.json`，没有 `node_modules`，**没有构建步骤**
- 微信开发者工具打开即编译，上传即打包
- 语言就是官方四件套：`WXML` / `WXSS` / `JS` / `JSON`

判断标准很简单：根目录有 `project.config.json` 且 `miniprogramRoot` 指向 `miniprogram/`，这就是标准的小程序工程结构。

---

## 二、环境要求

| 用途 | 需要 |
|---|---|
| 开发 / 调试 / 发布 | 微信开发者工具（稳定版） |
| 本地网页预览（可选） | Node.js 18+ |
| 代码托管 | Git |

---

## 三、首次导入（同事上手）

1. 克隆仓库
   ```bash
   git clone <仓库地址>
   ```
2. 打开微信开发者工具 → 导入项目
3. **目录选择仓库根目录**（含 `project.config.json` 的那一层），不要选 `miniprogram/`
4. AppID 填团队的小程序 AppID（见下一节）
5. 编译，从「工作台 → 新建标书 → 使用示例文件」开始自测

> 想不装开发者工具先看效果：`node tools/preview/server.js`，浏览器打开 `http://127.0.0.1:5199`。

---

## 四、AppID 配置

当前 `project.config.json` 里是 `touristappid`（游客模式，只能本地预览，**不能上传**）。

替换方式二选一：

1. **改 `project.config.json` 的 `appid` 字段**（推荐，团队统一）
2. 在开发者工具「详情 → 基本信息」里改（会写入 `project.private.config.json`，该文件已被 git 忽略）

AppID 不是密钥，提交到仓库是常规做法；真正需要保密的是 AppSecret（后端才用，不要放进小程序代码）。

## 五、目录职责

| 路径 | 是否打包上传 | 说明 |
|---|:--:|---|
| `miniprogram/` | ✅ | **唯一被打包的内容**，所有页面与逻辑 |
| `project.config.json` | ❌ | 工程配置，仅开发者工具读取 |
| `tools/preview/` | ❌ | 本地网页预览器，开发辅助 |
| `docs/` | ❌ | 产品与竞品文档 |
| `.workbuddy-ai/` | ❌ | AI 助手项目记忆，已 git 忽略 |

> 关键点：因为 `miniprogramRoot` 是 `miniprogram/`，**根目录其它文件都不会进入小程序包**，不会影响体积和审核。

## 六、Git 协作约定

**分支**
- `main`：可发布状态，随时能上传体验版
- `feat/xxx`、`fix/xxx`：功能与修复分支，合并前自测

**提交前自测清单**
- [ ] 开发者工具编译无报错、无警告
- [ ] 主链路能走通：工作台 → 新建 → 解析 → 报告 → 大纲 → 生成 → 章节 → 导出
- [ ] 改过 `app.json` 的页面要确认路由仍可跳转
- [ ] 没有把真实招标文件、客户资料提交进仓库

**容易冲突的文件**
- `app.json`（路由与 tabBar）：多人同时加页面时先沟通
- `utils/mock.js`（测试数据）：改动前确认没有别人正在改
- `app.wxss`（全局样式）：新增全局类名前先搜一遍是否重名

**不要提交**
- `project.private.config.json`（个人编译设置）
- `node_modules/`、`miniprogram_npm/`
- 招标文件 PDF、投标文件、客户资料

## 七、发布流程

```
开发者工具「上传」 → 微信公众平台「版本管理」 → 设为体验版 → 提交审核 → 审核通过 → 发布
```

1. **上传**：开发者工具右上角「上传」，填版本号（如 `1.0.0`）和备注
2. **体验版**：公众平台 → 管理 → 版本管理 → 选中刚上传的版本 → 设为体验版，把二维码发给同事/客户试用
3. **提交审核**：填写功能页面、类目、测试账号（如有登录）
4. **发布**：审核通过后点「发布」，可选择全量或分阶段发布

**版本号建议**：`主版本.次版本.修订号`，功能上线加次版本，修 bug 加修订号。

## 八、上线前置清单（当前项目尚未满足）

| 项 | 状态 | 说明 |
|---|:--:|---|
| 小程序 AppID + 企业主体 | ⬜ | 个人主体无法开通微信支付 |
| 服务类目 | ⬜ | 需在公众平台选择并可能提交资质 |
| 隐私协议 | ⬜ | 涉及上传文件，必须配置用户隐私保护指引 |
| 服务器域名 | ⬜ | 接后端后需 HTTPS + ICP 备案，并加入 request 合法域名 |
| 真实业务能力 | ⬜ | 当前为测试数据，AI 解析/生成/支付均为模拟 |
| 生成式 AI 合规 | ⬜ | 面向公众提供 AI 生成服务需评估备案要求 |
| tabBar 图标 | ⬜ | 当前为纯文字，建议补 81×81 图标 |

> 现阶段可以正常「上传 + 体验版」，但**不建议提交正式审核**——功能是演示数据，审核大概率不通过，也会误导试用者。

## 九、新人 5 分钟上手

1. 克隆仓库，开发者工具导入根目录
2. 读 `README.md` 了解主链路
3. 读 `miniprogram/utils/mock.js` 了解数据结构
4. 跑 `node tools/preview/server.js`，点一遍全部页面
5. 从 `pages/index/index` 开始读代码，按 `app.json` 的 pages 顺序往下看
